온라인 메뉴판은 **사진이나 PDF가 아니라 웹페이지 본문에 글자로 쓴 메뉴**가 기본이어야 합니다. 글자로 된 메뉴는 폰에서 스크롤만으로 읽히고, 구글과 AI 검색이 메뉴 이름과 가격을 읽을 수 있으며, 가격이 바뀌면 몇 글자만 고치면 됩니다. 사진과 PDF는 지울 필요 없이 **보조 자료**로 남겨 두면 됩니다.

"메뉴판은 이미 올려놨는데요." 식당 사장님들께 가장 자주 듣는 말입니다. 그런데 열어 보면 스마트폰으로 찍은 메뉴판 사진이거나, 인쇄용 PDF를 그대로 링크한 경우가 대부분입니다. 사장님 눈에는 메뉴가 올라가 있지만, 손님의 폰 화면과 검색 로봇에게는 읽기 어려운 그림에 가깝습니다. 이 글은 메뉴를 **읽히는 형태**로 올리는 순서, 구글 비즈니스 프로필(구글 지도에 나오는 가게 정보)과 연결하는 방법, 가격이 틀어지지 않게 관리하는 요령을 정리합니다. 식당뿐 아니라 카페, 베이커리, 네일·미용실, 학원처럼 **가격표가 있는 모든 업종**에 그대로 적용됩니다. (2026년 11월 기준 구글 고객센터 안내를 바탕으로 썼습니다.)

## 사진·PDF 메뉴는 왜 문제가 될까요?

![사진·PDF 메뉴와 텍스트 메뉴 페이지를 폰 읽기, 검색·AI 인식, 번역, 가격 수정 네 가지로 비교한 표](/blog-img/online-menu-guide-photo-vs-text-compare2.png)

- **폰에서 읽기 어렵습니다.** 인쇄용 크기의 PDF는 폰에서 확대·축소·좌우 이동을 반복해야 하고, 손님은 가격 하나 확인하려다 뒤로 가기를 누르기 쉽습니다.
- **검색이 메뉴 이름을 정확히 읽는다는 보장이 없습니다.** 구글은 PDF 안의 글자를 색인할 수 있지만, 메뉴판을 찍은 사진이나 스캔한 PDF는 사실상 그림입니다. 그러면 "갈비탕", "순두부" 같은 메뉴 이름이 검색과 연결되기 어렵습니다. AI가 사진 속 글자를 읽는 방식과 한계는 [사진 속 글자는 AI가 못 읽는다?](/blog/text-in-images-ai-search/)에 따로 정리했습니다.
- **번역과 화면 읽기 프로그램이 통하지 않습니다.** 현지 손님이 브라우저 번역을 켜도 이미지 속 한글은 번역되지 않고, 화면 읽기 프로그램을 쓰는 손님은 메뉴를 전혀 이용할 수 없습니다.
- **수정이 번거로워 옛 가격이 방치됩니다.** 가격이 바뀔 때마다 이미지를 다시 디자인해야 해서, 결국 몇 달씩 옛 가격이 그대로 남기 쉽습니다.
- **용량이 커서 느립니다.** 고화질 메뉴판 사진 여러 장이나 큰 PDF는 폰 데이터에서 늦게 열립니다. 느린 사이트를 고치는 방법은 [모바일에서 느린 가게 사이트 고치는 법](/blog/slow-mobile-website-fix/)을 참고하세요.

**PDF가 무조건 나쁜 것은 아닙니다.** 인쇄용·단체 주문용·케이터링 메뉴로는 여전히 편리합니다. 문제는 PDF가 **유일한** 메뉴일 때입니다.

## 손님이 읽기 쉬운 메뉴 페이지는 어떻게 생겼나요?

![폰 화면에서 카테고리 바로가기, 메뉴 이름·설명·가격, 전화·주문 버튼 순서로 구성한 메뉴 페이지 구조도](/blog-img/online-menu-guide-menu-page-phone.png)

화려한 디자인은 필요 없습니다. 아래 구조만 지켜도 사진 메뉴보다 훨씬 낫습니다.

1. **카테고리 바로가기**: 페이지 위쪽에 "찌개·탕 / 구이 / 식사 / 음료"처럼 카테고리 버튼을 두고 누르면 해당 위치로 이동하게 합니다.
2. **카테고리별 제목**: 각 카테고리를 제목(웹페이지의 `h2`, `h3` 제목 태그)으로 나눕니다.
3. **메뉴마다 이름 · 한 줄 설명 · 가격**을 글자로 씁니다.
4. **대표 메뉴 3~5개에만 사진**을 붙이고, 사진에는 메뉴 이름이 들어간 대체 텍스트(alt, 이미지를 설명하는 글자)를 답니다.
5. **알레르기·매운 정도·채식 가능 여부**를 메뉴 옆에 짧게 표시합니다.
6. **전화·주문·예약 버튼**을 페이지 위나 아래에 고정해, 메뉴를 고른 손님이 바로 행동하게 합니다.
7. 폰 화면(가로 360px 정도)에서 직접 열어 한 번에 스크롤하며 읽히는지 확인합니다.

### 메뉴 한 줄은 이렇게 씁니다 (예시 문구)

예를 들어 한식당이라면 아래처럼 한글 이름, 영어 이름, 짧은 설명, 가격을 한 줄에 담습니다. 아래 메뉴와 가격은 설명을 위한 가상의 예시입니다.

- `갈비탕 Galbitang (Beef Short Rib Soup) — 소갈비를 오래 끓인 맑은 탕, 밥 포함 · $18.99`
- `해물순두부 Seafood Soft Tofu Stew (Spicy) — 새우·조개·오징어, 매운 정도 선택 가능 · $17.99`
- `잡채 Japchae (Glass Noodles) — 고구마 당면과 채소 볶음, 채식 주문 가능 · $14.99`

영어 이름만 쓰면 현지 손님이 무엇인지 모를 수 있으니 **괄호 안 설명(주재료·조리법)**을 붙이는 것이 핵심입니다. 반대로 한국 손님은 한글 이름으로 찾으므로 한글을 지우면 안 됩니다. 두 언어를 함께 운영하는 요령은 [한국어로 물어도 우리 가게가 나올까](/blog/korean-language-ai-search/)에서도 다룹니다.

### 업종별로 무엇을 '메뉴'로 올릴까요?

| 업종 | 글자로 올릴 내용 | 함께 적으면 좋은 정보 |
|---|---|---|
| 한식당·분식 | 메뉴 이름(한·영), 설명, 가격 | 매운 정도, 알레르기, 1인분 기준 |
| 카페·베이커리 | 음료·빵 이름, 사이즈별 가격 | 우유 변경·디카페인 가능 여부, 시즌 메뉴 기간 |
| 네일·미용실 | 시술 이름, 가격 또는 "부터" 가격 | 소요 시간, 길이·디자인에 따른 추가 비용 기준 |
| 안경점 | 렌즈·검안 등 서비스 항목 | 보험 처리 여부 안내, 소요 기간 |
| 학원·교습소 | 과정 이름, 대상 학년, 수업 횟수 | 수강료 기준(월·학기), 교재비 별도 여부 |

가격이 상담 뒤에 정해지는 업종은 정확한 가격 대신 **"$45부터"처럼 시작 가격과 기준**을 적어도 됩니다. "가격 문의"만 적어 두면 손님이 비교 단계에서 다른 가게로 넘어가기 쉽습니다.

## 메뉴 페이지를 만들기 전에 점검할 것

- [ ] 메뉴 이름·설명·가격이 전부 **손가락으로 길게 눌러 복사되는 글자**인가
- [ ] 한글 이름과 영어 이름(+짧은 설명)이 함께 있는가
- [ ] 가격이 실제 매장 가격과 같은가 (배달 앱 가격이 다르면 그 사실을 적었는가)
- [ ] 품절·시즌 메뉴를 사장님이 직접, 5분 안에 고칠 수 있는 구조인가
- [ ] 폰에서 3초 안에 원하는 카테고리까지 갈 수 있는가
- [ ] 페이지 제목에 업종과 지역이 들어가는가 (예: "얼바인 한식당 메뉴 | 가게 이름")
- [ ] 메뉴판 QR 코드가 PDF가 아니라 이 페이지로 연결되는가
- [ ] PDF는 "인쇄용 메뉴 다운로드" 링크로만 남겨 두었는가

메뉴판 사진을 손으로 타이핑하기 번거롭다면 [메뉴판 → 웹 메뉴 변환기](/tools/menu-to-web/) 같은 도구로 먼저 글자를 뽑은 뒤, **가격과 철자를 한 줄씩 대조**하세요. 사진 인식은 숫자를 잘못 읽을 수 있습니다.

## 구글 비즈니스 프로필에 메뉴를 넣는 방법

구글 프로필에는 메뉴를 넣는 길이 여러 개 있습니다. 구글 고객센터의 [메뉴 편집기 안내](https://support.google.com/business/answer/9455840?hl=en) 기준으로 정리하면 다음과 같습니다.

| 방법 | 어디서 | 알아둘 점 |
|---|---|---|
| **메뉴 편집기** | 프로필 화면의 '메뉴 수정(Edit menu)' | 음식·음료 업종에서 제공. 섹션과 메뉴 이름·설명·가격을 직접 입력. 반영까지 24~48시간 걸릴 수 있음 |
| **메뉴 사진으로 메뉴 만들기** | 메뉴 수정 → 메뉴 사진 업로드 → 메뉴 생성 | 구글이 **실험 기능**이라고 명시. 메뉴 전체가 한 페이지·사진 한 장에 담기고 선명해야 함. 생성 결과를 꼭 검토한 뒤 게시 |
| **메뉴 링크** | 프로필 수정 → 비즈니스 정보 → 연락처 → 메뉴 링크 | 웹사이트의 **텍스트 메뉴 페이지 주소**를 넣음 |
| **메뉴 사진** | 메뉴 수정 → 메뉴 사진 | 사진·PDF 업로드 가능. 손님이 올린 옛 메뉴판 사진은 신고하고 최신 사진을 올림 |
| **웹사이트 메뉴 자동 반영** | 별도 입력 없음 | 구글이 가게 웹사이트의 메뉴를 프로필로 옮겨 적을 수 있음. 틀리면 프로필에서 고치거나 삭제 |

순서는 이렇게 권합니다.

1. 웹사이트에 텍스트 메뉴 페이지를 먼저 만듭니다. 이것이 **원본**입니다.
2. 프로필 '메뉴 링크'에 그 페이지 주소를 넣습니다.
3. 음식·음료 업종이면 메뉴 편집기에 대표 메뉴부터 이름·설명·가격을 입력합니다. 웹 메뉴와 **이름과 가격을 똑같이** 맞춥니다.
4. 메뉴 사진은 최신 메뉴판으로 교체하고, 손님이 올린 옛 가격 사진이 보이면 신고합니다.
5. 24~48시간 뒤 구글 지도에서 가게를 검색해 메뉴 탭이 제대로 보이는지 확인합니다.

**인기 메뉴(Popular dishes)도 확인하세요.** 구글 지도 앱에서는 사장님과 손님 모두 음식 사진에 메뉴 이름을 붙일 수 있고, 구글은 사장님이 붙인 이름을 우선한다고 안내합니다([인기 메뉴 안내](https://support.google.com/business/answer/9322475?hl=en)). 다만 수정 제안이 반드시 반영된다는 보장은 없습니다. 메뉴가 아닌 서비스 업종(네일·미용실·치과 등)은 메뉴 편집기 대신 서비스 항목을 채웁니다 — [구글 프로필 서비스·상품 항목 채우는 법](/blog/google-business-profile-services-guide/)을 참고하세요.

## 웹사이트에 메뉴 스키마(구조화 데이터)를 넣어야 하나요?

스키마(구조화 데이터)는 검색엔진이 읽는 "가게 정보 꼬리표"입니다. 구글의 [로컬 비즈니스 구조화 데이터 문서](https://developers.google.com/search/docs/appearance/structured-data/local-business)는 음식점의 `menu` 속성을 "메뉴의 전체 URL"로 설명하고 권장 속성에 넣어 두었습니다. 그러니 가게 정보 스키마에 **메뉴 페이지 주소 하나**를 넣는 것은 해볼 만합니다.

다만 같은 문서에는 메뉴 항목을 별도로 보여 주는 "메뉴 리치 결과"가 나오지 않습니다(2026년 11월 확인). 메뉴 하나하나를 스키마로 정교하게 표시하는 작업보다 **화면에 보이는 글자 메뉴를 정확하게 유지하는 것**이 먼저입니다. 스키마 설정 전체는 [AI가 읽기 좋은 가게 웹사이트](/blog/ai-friendly-website-setup/)에 정리했습니다.

## 가격이 틀리면 신뢰를 잃습니다 — 관리 요령

| 상황 | 해야 할 일 | 주기 |
|---|---|---|
| 가격 인상 | 웹 메뉴 → 구글 프로필 메뉴 → 배달 앱 → 매장 메뉴판 순서로 똑같이 수정 | 변경 당일 |
| 시즌·한정 메뉴 | 별도 섹션으로 표시하고 시작일·종료일을 함께 적음 | 시즌마다 |
| 품절이 잦은 메뉴 | "재료 소진 시 종료" 문구를 메뉴 옆에 표시 | 상시 |
| 배달 앱 가격이 다름 | 웹 메뉴에 "배달 앱 가격은 매장과 다를 수 있습니다" 한 줄 | 상시 |
| 휴무·영업시간 변경 | 메뉴 페이지와 구글 프로필 영업시간을 함께 수정 | 변경 당일 |
| 전체 점검 | 웹·구글 프로필·배달 앱 세 곳을 나란히 열어 비교 | 월 1회 |

영업시간을 바꿀 때 구글 프로필에 반영하는 방법은 [영업시간·휴무일 변경 반영하는 법](/blog/google-business-profile-hours-update/)을 참고하세요.

### 알레르기·영양 정보는 어디까지 적어야 하나요?

- **칼로리 표시 의무는 대형 체인에 해당합니다.** 미국 FDA의 메뉴 표시 규정은 **같은 이름으로 20개 이상 매장을 운영하며 같은 메뉴를 파는 체인**에 칼로리 표시를 요구합니다([FDA 메뉴 표시 요건](https://www.fda.gov/food/nutrition-food-labeling-and-critical-foods/menu-labeling-requirements)). 대부분의 개인 한인 식당은 대상이 아니지만, 체인 가맹점이라면 본사 기준을 확인하세요.
- **알레르기 표시는 손님 안전과 신뢰의 문제입니다.** FDA가 정한 주요 알레르기 식품은 우유·달걀·생선·갑각류·견과류·밀·땅콩·대두·참깨 9가지입니다(참깨는 2023년부터 추가). 한식은 참깨·참기름·대두(간장·된장)·밀이 들어가는 메뉴가 많으니 메뉴 옆에 짧게 적어 두면 도움이 됩니다.
- 주·시 단위로 별도 규정이 있을 수 있습니다. 확실하지 않으면 관할 보건국 안내를 확인하세요.

## 이럴 땐 하지 마세요 — 흔한 실수

- **메뉴판 사진만 올리고 끝내기.** 사진은 보조입니다. 같은 내용을 반드시 글자로 한 번 더 적으세요.
- **QR 코드를 PDF에 연결하기.** 테이블 QR이 PDF로 열리면 폰에서 확대를 반복해야 합니다. QR은 텍스트 메뉴 페이지로 연결하세요.
- **메뉴를 여러 곳에서 따로 관리하기.** 웹, 구글, 배달 앱, 인스타그램에서 각각 다른 버전을 고치다 보면 가격이 어긋납니다. 웹 메뉴를 원본으로 정하고 나머지는 그 내용을 따라 고칩니다.
- **"시가"·"가격 문의"를 남발하기.** 정말 매일 바뀌는 메뉴가 아니라면 범위나 시작 가격을 적는 편이 신뢰를 얻습니다.
- **AI가 만든 메뉴를 검토 없이 게시하기.** 구글의 '메뉴 사진으로 메뉴 만들기'도, 변환 도구도 숫자를 틀릴 수 있습니다. 게시 전 가격을 한 줄씩 확인하세요.

**솔직한 주의사항**: 온라인 메뉴는 "올리는 것"보다 **"틀리지 않게 유지하는 것"**이 훨씬 어렵습니다. 웹·구글·배달 앱 가격이 서로 다르면 손님은 가장 싼 곳을 기준으로 기대하고, 매장에서 다른 가격을 만나면 그 불만이 리뷰로 돌아올 수 있습니다. 관리할 여력이 없다면 온라인에 올리는 메뉴 수를 줄이고 대표 메뉴만 정확하게 유지하는 편이 낫습니다.

웹사이트 전체를 어떤 순서로 손볼지는 [가게 웹사이트 완전 가이드](/blog/website-hub/)에서 단계별로 볼 수 있습니다.

## 자주 묻는 질문

### PDF 메뉴는 아예 쓰면 안 되나요?
쓰지 말아야 하는 것은 아니지만 **유일한 메뉴**로 두면 안 됩니다. 기본 메뉴는 텍스트 페이지로 두고, PDF는 인쇄용·단체 주문용 "다운로드" 링크로 보조하는 것이 좋습니다. 구글은 글자가 들어 있는 PDF를 색인할 수 있지만, 메뉴판을 스캔하거나 사진으로 만든 PDF는 글자로 읽힌다는 보장이 없습니다.

### 웹사이트가 없으면 메뉴를 어디에 올려야 하나요?
음식·음료 업종이라면 구글 비즈니스 프로필의 메뉴 편집기에 메뉴 이름·설명·가격을 직접 입력하는 것부터 시작하세요. 메뉴 사진도 함께 올리되 최신 가격인지 확인합니다. 다만 프로필 안에서는 구성과 언어 병기에 한계가 있으므로, 메뉴가 많거나 자주 바뀐다면 메뉴 페이지가 있는 간단한 웹사이트를 따로 두는 편이 관리하기 쉽습니다.

### 구글 프로필에서 메뉴를 고쳤는데 바로 안 바뀌어요.
구글 안내에 따르면 메뉴 변경이 구글 지도와 검색에 보이기까지 24~48시간이 걸릴 수 있습니다. 이틀이 지나도 옛 메뉴가 보이면 웹사이트 메뉴가 옛 내용인지 먼저 확인하세요. 구글이 웹사이트 메뉴를 프로필로 옮겨 적을 수 있기 때문입니다.

### 메뉴 사진은 몇 장이 적당한가요?
모든 메뉴에 사진을 넣을 필요는 없습니다. 대표 메뉴 3~5개에 밝고 선명한 사진을 붙이고 나머지는 글자 설명으로 충분합니다. 사진이 많을수록 폰에서 로딩이 느려질 수 있습니다. 음식 사진 찍는 요령은 [손님을 부르는 가게 사진 찍는 법](/blog/store-photo-guide/)을 참고하세요.

### 한글 메뉴 옆에 영어를 꼭 써야 하나요?
현지 손님을 받고 싶다면 권장합니다. 영어 이름만이 아니라 "주재료", "매운 정도", "채식 가능 여부"를 괄호나 한 줄 설명으로 덧붙이면 주문을 망설이는 일이 줄어듭니다. 한국 손님이 한글로 찾는 경우도 많으니 한글 이름은 그대로 두세요.
