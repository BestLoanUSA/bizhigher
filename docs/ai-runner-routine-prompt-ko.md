(ㄴ) 재배포 조건 — 다음 중 하나면 등록된 사이트가 1곳 이상일 때 `node automation/ai-runner/sites.js build --out {스크래치}/sites-build && node automation/ai-runner/sites.js deploy --dir {스크래치}/sites-build` 로 전 고객 사이트를 한 번 재배포한다(머지된 템플릿·라우터 수정, 관리자에서 바꾼 스타일·등급, 고객이 고객 페이지에서 고른 스타일이 전 고객 사이트에 반영되는 경로. 바뀐 파일만 올라가므로 가볍다. 결과를 요약에 한 줄로): ① 현재 LA 시각(America/Los_Angeles)이 07시대(정기 실행) ② `node automation/ai-runner/sites.js needs-deploy` 가 "yes" 로 시작하는 줄을 출력(템플릿·라우터가 마지막 배포 뒤 바뀜, 또는 관리자·고객 선택으로 스펙이 바뀜). items·pendingDrafts 가 둘 다 비어 있으면 "오늘 AI 차례 없음"이라고 요약하고 끝낸다.
2. items의 단계마다 job.intake(질문지)·job.profile·job.done_results(이미 만든 결과물)·task.revise_note(David 또는 고객의 수정 요청 — "[고객 수정 요청]"으로 시작하면 고객이 고객 페이지에서 남긴 것)·task.note(David 메모 또는 "[고객 선택] B — 라벨" = 고객이 고객 페이지에서 고른 선택지)·task.prev_result_text 를 읽고, 그 서비스 플레이북에 맞는 결과물을 만든다. 한 번 실행에 최대 12단계. task.verify 가 false 면 submit 에 `--done` 을 붙여 바로 완료한다. 한국어로 쓰되 고객 언어가 한/영이면 영문도 붙인다. task.revise_note 가 있으면 그 지시를 최우선으로 따르고, 이전 결과물(prev_result_text)에서 David가 고친 값은 유지한다. submit 응답이 "자동 승인"이면 관리자 규칙에 따라 바로 완료된 것이니 그대로 집계한다.
   **고객이 고르는 승인(공용)**: 시안·세트·버전·영상·사이트 스타일처럼 고객이 하나를 골라야 하는 결과물은 `runner.js submit … --options {파일}.json` 으로 올린다. 형식은 `[{"key":"A","label":"짧은 이름","image":"https://…/a/….jpg","video":"https://…/a/….mp4(영상일 때만)","note":"한 줄 설명","styles":["editorial","warm"],"default":false,"patch":{…사이트 스펙 부분 패치, 웹사이트 스타일 선택만}}]` — image·video 는 반드시 upload 로 올린 공개 URL, key 는 A/B/C 또는 1/2/3 또는 스타일 키. 고객 페이지에 카드로 뜨고(영상은 재생됨) 고객이 고르면 같은 서비스의 다음 단계 task.note 에 "[고객 선택] B — 라벨"이 들어온다(patch 가 있으면 사이트 스펙에 그 자리에서 적용되고 다음 실행의 needs-deploy 가 yes). 무응답 7일이면 사이트 스타일(styles)에 맞는 것 → default → 첫 항목으로 자동 선택된다. 결과물 본문 첫 줄에 고객이 읽을 안내("아래 세 가지 중 하나를 골라 주세요" 등)를 쓴다. 지금 켜진 곳: 리뷰 QR 시안(qr-2) · 광고 소재 세트(ac-5) · 웹사이트 스타일(web-2) · 영상(sv-2)
